# Разработка RS Advanced

## Структура

- `common` — определения ячеек, компоненты предметов, механика источников,
  интеграция с RS, клиентское оформление и обычные JSON-ресурсы.
- `fabric` / `neoforge` — регистрация синхронизируемого реестра через API загрузчика
  и сборка выпускных JAR на Architectury.
- `common/src/gameTest` — отдельный тестовый мод; в выпуск не включается.

Java 21, Minecraft 1.21.1, Refined Storage 2.0.9. Внутренние обёртки RS используются
через Mixin: изменение версии RS требует повторной проверки.

## Добавление ячейки через датапак

Java и datagen не нужны. Встроенные определения находятся в
`common/src/main/resources/data/rsadvanced/rsadvanced/infinite_cell`.
Внешний датапак устанавливается в `<мир>/datapacks/<имя-пака>`.
Готовый пример: [lava-datapack](examples/lava-datapack).

Структура внешнего пака:

```text
lava-datapack/
├── pack.mcmeta
└── data/my_pack/
    ├── rsadvanced/infinite_cell/lava.json
    └── recipe/infinite_lava_cell.json
```

`pack.mcmeta` для Minecraft 1.21.1:

```json
{
  "pack": {
    "pack_format": 48,
    "description": "Infinite lava cell for RS Advanced"
  }
}
```

`data/my_pack/rsadvanced/infinite_cell/lava.json`:

```json
{
  "kind": "fluid",
  "resource": "minecraft:lava"
}
```

ID определения — `my_pack:lava`. Для предмета задайте `"kind": "item"`
и ID зарегистрированного предмета, например `minecraft:iron_ingot`.
Компоненты самого ресурса и химикаты на этом этапе не поддерживаются.
Ресурс может принадлежать другому установленному моду.

Название берётся из отображения ресурса RS и перевода клиента:
«Бесконечная ячейка (Лава)» / `Infinite Cell (Lava)`.
Копировать перевод ресурса, задавать текстуру или регистрировать новый предмет
для каждого определения не нужно. Предметные и жидкостные ячейки используют
две общие иконки и стандартные модели дисков RS в приводе.
Подсказки используют штатную помощь RS: описание раскрывается при удержании Shift.
Ресурс-пак может менять переводы и оформление стандартными средствами Minecraft.

## Рецепт и выдача предмета

Рецепты — отдельные стандартные JSON. Список определений автоматически
наполняет основную творческую вкладку Refined Storage, но не создаёт рецепты для произвольных ресурсов:
ингредиенты выбирает автор сборки.

`data/my_pack/recipe/infinite_lava_cell.json`:

```json
{
  "type": "minecraft:crafting_shapeless",
  "category": "misc",
  "ingredients": [
    { "item": "refinedstorage:storage_housing" },
    { "item": "minecraft:lava_bucket" }
  ],
  "result": {
    "id": "rsadvanced:infinite_fluid_disk",
    "count": 1,
    "components": {
      "rsadvanced:cell_definition": "my_pack:lava"
    }
  }
}
```

Для предметного ресурса результатом должен быть `rsadvanced:infinite_item_disk`.
Вёдра возвращаются штатным механизмом рецептов Minecraft. При необходимости
добавьте стандартное достижение для открытия рецепта в книге.

```mcfunction
/give @s rsadvanced:infinite_fluid_disk[rsadvanced:cell_definition="my_pack:lava"]
```

Установите датапак до открытия мира или запуска сервера. Для существующего
мира полностью выйдите из него, установите файлы и откройте снова.
`/reload` обновляет рецепты, но каталог определений фиксируется на сеанс.
Обычные приоритеты датапаков позволяют переопределить встроенный ID.
Невалидный вид, отсутствующий или пустой ресурс отклоняет загрузку реестра;
Minecraft указывает файл/ID определения в диагностике.

Клиент получает определения при подключении. Копировать серверный датапак
на клиент не требуется; версия аддона на клиенте и сервере должна совпадать.
Внешние моды, ресурсы которых используются в определениях, должны быть
установлены согласно их собственным требованиям.

## Сохранение и механика

`rsadvanced:cell_definition` хранит ID определения в ItemStack и передаётся
штатным кодеком компонентов Minecraft. Источник RS сохраняет только этот ID,
без UUID и накопленного количества. Зарегистрированы два типа хранилищ:
`rsadvanced:infinite_item` и `rsadvanced:infinite_fluid`.
Создание хранилища без определения запрещено.

Если определение исчезло, предмет с его ID сохраняется и показывает
«Неизвестная бесконечная ячейка» с диагностикой. Он не создаёт источник.
После восстановления определения и переоткрытия мира тот же предмет работает.
Вид универсального предмета должен совпадать с `kind` определения.

Обратной совместимости с прежними ID предметов и типов хранилищ нет.
Миграции старых ячеек не предусмотрены.

Ячейка отдаёт свой ресурс и поглощает возвращённый ресурс без накопления.
Приоритеты, фильтры, доступ и питание остаются под управлением RS.
Числовой запас в API RS — постоянный миллиард единиц на источник;
это виртуальная доступность, а не физически сохранённый запас.
Признак ∞ передаётся отдельно набором доступных ResourceKey, без битовой маски.
Числовая статистика Disk Drive считает только обычные диски. Единая строка
бесконечных ресурсов перечисляет установленное содержимое независимо от питания.

Квоты Disk Interface находятся в `DiskResourceKind`: 1/64 предмета или 1/16
платформенных вёдер без/со Stack Upgrade. Квоты Exporter и вместимость целевого
инвентаря определяются RS и обработчиком целевого контейнера.

## Сборка и проверки

```powershell
.\gradlew.bat clean build
```

Отдельные проверки:

```powershell
.\gradlew.bat :common:test
.\gradlew.bat :fabric:runGameTest
.\gradlew.bat :neoforge:runGameTest
```

Тесты загружают пример лавы как внешний датапак в тестовом мире, а тестовый мод
добавляет более 31 определения и ресурс RS. Запуски двух GameTest упорядочены
Fabric → NeoForge из-за блокировки общего агента Architectury на Windows.

Для проверки настоящего подключения клиента, локализации и ресурс-пака
используйте два терминала с одинаковым загрузчиком:

```powershell
# Терминал 1 — GameTest-сервер с локальным портом и внешним датапаком.
.\gradlew.bat :fabric:runServerValidation
# Терминал 2 — клиент автоматически подключается, выполняет проверки и закрывается.
.\gradlew.bat :fabric:runClientValidation
```

Для NeoForge замените `fabric` на `neoforge`. Порты: 25575 и 25576.
Сервер слушает только loopback; после выхода клиента проверка завершается.
Тестовый перевод устанавливается в отдельном клиентском ресурс-паке.
Эти запуски не входят в обычный `build`, поскольку требуют графического окружения.

Отчёты: `common/build/reports/tests/test`, `<loader>/build/reports/gameTest/results.xml`,
`<loader>/build/reports/clientValidation/results.txt`.
Ручные визуальные сценарии перечислены в [VALIDATION.md](../VALIDATION.md).
